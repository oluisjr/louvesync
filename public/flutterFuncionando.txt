1. Erro ao salvar membro no banco de dados
O erro está em saveMember() no PainelAdmin (linha 596–618). O objeto enviado ao Supabase inclui campos que muito provavelmente não existem como colunas na tabela members:
jsconst dbMember = { ...newMember };
delete dbMember.permissions;
delete dbMember.unavailableDays;
// ⚠️ Ainda envia: pin, vocal_category, confirmRate, etc.
const saved = await upsertMember(dbMember);
Causa mais provável: a tabela members no Supabase não tem coluna pin (ou vocal_category), então o upsert falha com erro de schema. Além disso, membros novos criados na UI provavelmente recebem um id no formato 'new_' + Date.now() ou sem UUID, o que o Supabase rejeita se a coluna id é do tipo uuid.
Fix:
jsconst saveMember = async () => {
  if(!editMember.name || !editMember.pin) return alert('Nome e PIN são obrigatórios!');
  const newMember = {...editMember};
  // garante UUID válido para novos membros
  if (!newMember.id || newMember.id.startsWith('new_')) {
    newMember.id = crypto.randomUUID();
  }
  setMembers(mList => {
    const exists = mList.find(m => m.id === newMember.id);
    if (exists) return mList.map(m => m.id === newMember.id ? newMember : m);
    return [...mList, newMember];
  });
  setEditMember(null);
  try {
    // Enviar apenas colunas que existem no Supabase
    const { permissions, unavailableDays, confirmRate, pin, ...dbMember } = newMember;
    const saved = await upsertMember(dbMember);
    if (saved) {
      setMembers(mList => mList.map(m => m.id === newMember.id ? {...newMember, ...saved} : m));
    }
  } catch (e) {
    console.error('Failed to save member:', e);
    alert('Erro ao salvar membro: ' + (e.message || 'Verifique o console.'));
  }
};

Nota: Se precisar do pin para login, ele deve viver apenas no localStorage / estado local, nunca ir pro banco pelo anon key (qualquer usuário logado consegue ler todos os PINs via REST).


2. PWA instalado não atualiza após novo deploy no Vercel
Causa clássica de PWA: o Service Worker (SW) faz cache do app shell (index.html, JS, CSS). Quando você faz deploy no Vercel, o browser ainda serve a versão cacheada. O SW só percebe a atualização em background, e a nova versão só é ativada quando todas as abas do app são fechadas — a menos que skipWaiting esteja configurado.
Como o projeto usa Vite (provavelmente com vite-plugin-pwa), a correção é no vite.config.js:
js// vite.config.js
import { VitePWA } from 'vite-plugin-pwa';

export default {
  plugins: [
    VitePWA({
      registerType: 'autoUpdate', // ← força atualização automática
      workbox: {
        skipWaiting: true,        // ← ativa novo SW sem esperar fechar abas
        clientsClaim: true,       // ← assume controle imediato das páginas
        cleanupOutdatedCaches: true,
      },
      // ... resto da config (manifest, icons, etc.)
    })
  ]
}
Opcionalmente, adicionar um aviso de "Nova versão disponível — recarregue" usando o hook useRegisterSW do plugin para UX mais explícita. Sem skipWaiting, o usuário precisa fechar todas as abas e reabrir para ver a nova versão.

Bug B — Cifra vem sem acordes (conteúdo vazio)
O teu teste com ScraperAPI funcionou perfeitamente — o HTML retornou os acordes em tags <b> dentro de <pre>. Isso confirma que o api/cifra.js atual não está usando proxy adequado e o CifraClub bloqueia o fetch direto (Cloudflare).
O flutterFuncionando.txt mostra que a URL do ScraperAPI funciona:
https://api.scraperapi.com/?api_key=2a48a74c3befd00c1780fe7834f217a9&url=https%3A%2F%2F...
Atualizar o api/cifra.js para usar ScraperAPI:
js// api/cifra.js
export default async function handler(req, res) {
  const { url } = req.query;
  if (!url) return res.status(400).json({ error: 'url required' });

  const SCRAPER_KEY = process.env.SCRAPERAPI_KEY; // adicionar no .env do Vercel
  const proxyUrl = `https://api.scraperapi.com/?api_key=${SCRAPER_KEY}&url=${encodeURIComponent(url)}&render=false`;

  try {
    const r = await fetch(proxyUrl, { headers: { 'Accept': 'text/html' } });
    if (!r.ok) return res.status(502).json({ error: 'scraper failed', status: r.status });
    
    const html = await r.text();
    
    // Extrai o bloco da cifra (cifra_cnt)
    const cifraMatch = html.match(/<div[^>]*class="[^"]*cifra_cnt[^"]*"[^>]*>([\s\S]*?)<\/div>\s*<\/div>/);
    const block = cifraMatch?.[1] || '';

    // Extrai o tom
    const keyMatch = html.match(/id="cifra_tom"[^>]*>([\s\S]*?)<\/span>/);
    const keyRaw = keyMatch?.[1]?.replace(/<[^>]+>/g,'').trim() || '';
    const key = keyRaw.match(/^[A-G][#b]?/)?.[0] || 'C';

    // Converte HTML → texto com acordes em [colchetes]
    const text = htmlToChordText(block || html);

    if (!text || text.length < 50) {
      return res.status(404).json({ error: 'cifra not found in page' });
    }

    res.setHeader('Cache-Control', 's-maxage=3600');
    return res.json({ text, key, title: '', artist: '', source: 'CifraClub' });
  } catch (err) {
    console.error('api/cifra error:', err);
    return res.status(500).json({ error: err.message });
  }
}

function htmlToChordText(html = '') {
  return html
    .replace(/<b>([A-G][^<\s]{0,10})<\/b>/gi, (_, c) => `[${c.trim()}]`)
    .replace(/<br\s*\/?>/gi, '\n')
    .replace(/<\/p>/gi, '\n')
    .replace(/<[^>]+>/g, '')
    .replace(/&amp;/g, '&').replace(/&nbsp;/g, ' ')
    .replace(/\n{4,}/g, '\n\n\n').trim();
}

4. Outros problemas encontrados
Além dos 3 bugs reportados, identifiquei:
a) handleSaveSong sempre cria registro novo ao editar (linha 2666):
jsconst {id:localId,...rest} = newSong;
const saved = await upsertSong({...rest, created_by:...}); // ← id removido!
Músicas editadas terão o id removido antes do upsert, então o Supabase insere uma nova linha em vez de atualizar. Fix: passar o id quando for uma edição (quando localId não começa com 'local_').
b) setSequenceForSong sendo usado para armazenar tom (linha 2542):
jsif(newKey && eventId) setSequenceForSong(eventId, songId, newKey) // ← errado
A função setSequenceForSong atualiza a coluna sequence (que deveria ser para sequência musical tipo "Intro, Verso 1..."), mas está recebendo o tom (ex: "D"). Isso corrompe o dado de sequência. Você precisa de uma coluna separada active_key em event_songs, ou usar keyBySong apenas localmente sem persistir via essa função.
c) Chave da API Groq exposta no frontend — import.meta.env.VITE_GROQ_API_KEY é visível no bundle JS do cliente. Qualquer usuário pode inspecionar e roubar a chave. O ideal é criar um endpoint /api/ai no Vercel que faça a chamada server-side, igual ao /api/cifra.
e) Limite do Maestro (IA) de 10 mensagens é hardcoded e não dá feedback claro ao usuário antes de travar. Adicionar um aviso quando aiCount >= 8 já seria boa UX.
